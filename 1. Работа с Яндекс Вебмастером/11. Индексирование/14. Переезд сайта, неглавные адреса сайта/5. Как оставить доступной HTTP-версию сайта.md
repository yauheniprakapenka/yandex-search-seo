Если сайт существует на двух разных протоколах, то одни и те же его страницы могут открываться по разным ссылкам:

- протокол HTTP — пример ссылки **http**://example.com;
- протокол HTTPS — пример ссылки **https**://example.com.

В таком случае *главным адресом* может стать сайт, который открывается по протоколу HTTPS. Это значит, что он может участвовать в поиске вместо HTTP-версии.

- Подробно: [Главный и неглавные адреса сайта](https://yandex.ru/support/webmaster/ru/yandex-indexing/site-addresses)

Если вы хотите, чтобы в поиске участвовала только HTTP-версия, укажите это Яндексу.

## Как указать HTTP-версию сайта как главную

Это можно сделать двумя разными способами:

### Настроить редиректы с HTTPS на HTTP

1. [Установите редирект](https://yandex.ru/support/webmaster/ru/yandex-indexing/moving-site#redirect) с HTTPS-страниц на аналогичные HTTP-страницы. При этом убедитесь, что [обе версии сайта доступны для робота](https://yandex.ru/support/webmaster/ru/yandex-indexing/moving-site#check).

2. Подайте заявку на переезд сайта с HTTPS на HTTP через инструмент Вебмастера [Переезд сайта](https://webmaster.yandex.ru/site/indexing/mirrors/). Это ускорит переезд и выявит возможные ошибки.

При редиректе доступными для посетителей будут только HTTP-страницы, так как редирект будет перенаправлять с HTTPS на HTTP-версию. В поиске после индексирования редиректа будет участвовать только HTTP-версия сайта.

Этот способ позволяет корректно передать показатели от версии к версии и правильно обработать запрос пользователя на версию сайта в поиске.

### Закрыть от роботов HTTPS-версию сайта

Полностью закройте от индексирования HTTPS-версию сайта с помощью директивы [Disallow](https://yandex.ru/support/webmaster/ru/robot-workings/allow-disallow#disallow) в файле `robots.txt`.

> **Пример**

```
User-agent: Yandex
Disallow: /
# запрещает роботам Яндекса индексирование и добавление в поиск всех страниц

User-agent: *
Disallow: /
# запрещает роботам всех поисковых систем индексирование и добавление в поиск всех страниц
```

Сайт в таком случае будет доступен для посетителей по обоим протоколам, но в поиске будет участвовать только HTTP-версия.

## Почему HTTPS предпочтительнее

Протокол HTTPS более безопасный и позволяет:

- снизить риск перехвата персональных данных посетителей, например, логинов, паролей, номеров банковских карт;
- избежать подмены контента (в том числе рекламы) при загрузке сайта.

Страницы на HTTP-протоколе могут обозначаться в некоторых браузерах как небезопасные, также их могут блокировать антивирусные приложения. Это может сделать сайт недоступным для посетителей.
