# Технологические партнеры, которые действуют от имени клиник

> Source: https://yandex.ru/support/webmaster/ru/search-appearance/clinic-agents

Сайты с информацией о врачах и медицинских услугах могут передавать данные в специальном формате в рамках [партнерской интеграции с поисковой системой Яндекса](https://yandex.ru/legal/search_partner_integration_policy). Эти данные могут быть отображены в поисковой выдаче. О передаче информации см. в разделе [Врачи](https://yandex.ru/support/webmaster/ru/search-appearance/doctors) Справки Вебмастера.

К партнерской интеграции также допускаются технологические партнеры, имеющие документально подтвержденные агентские договоры либо иные договорные конструкции, фактически реализующие агентскую схему взаимоотношений с минимум 10 клиниками (каждая с штатом не менее 10 врачей), предоставляющие право действовать от их имени. Яндекс оставляет за собой право запросить копии договоров и провести проверку на аффилированность с нарушителями условий размещения.

Подключение указанного количества клиник должно быть выполнено в течение 3 месяцев с момента регистрации в качестве технологического партнера. Яндекс может запрашивать подтверждение подключения непосредственно у клиник, а партнер обязуется передавать информацию о договорах через фид.

Технические требования включают возможность передачи фида для партнерской интеграции «Врачи» и возможность передачи онлайн-расписания в соответствии с требованиями, указанными в документации: [https://yandex.ru/dev/webmaster/doc/ru/reference/doctors-schedule](https://yandex.ru/dev/webmaster/doc/ru/reference/doctors-schedule) и в условиях партнерской интеграции.

## Какие дополнительные данные передают партнеры-агенты клиник

### Дополнительная группа в фиде

В [фид с данными](https://yandex.ru/support/webmaster/ru/search-appearance/doctors#yml) добавляется группа `agent_info`. Групп становится пять:

1. информация о врачах (`doctors`);
2. информация о клиниках (`clinics`);
3. информация об услугах (`services`);
4. информация о предложениях (`offers`);
5. информация об агенте (`agent_info`).

Пример:

```xml
<shop version="2.0" date="2024-12-10 08:06">
  <name>Яндекс.Здоровье</name>
  <company>ООО Яндекс.Врачи</company>
  <url>https://example.ru/</url>
  <doctors>...</doctors>
  <clinics>...</clinics>
  <services>...</services>
  <offers>...</offers>
  <agent_info>...</agent_info>
</shop>
```

### Как использовать элемент agent-info

Пример использования элемента agent_info:

```xml
<agent_info>
       <name>Агент</name>
       <company>ООО Пример-Агент</company>
       <url>https://agent.example.ru/</url>
       <picture>https://agent.example.ru/images/logo/agent.svg</picture>
       <email>help@agent.example.ru</email>
       <contract>Договор №1 от 10.12.2024</contract>
       <inn>770000000000</inn>
</agent_info>
```

[Пример полного заполнения фида данными (для агентов)](https://doc-static.yandex.net/src/support/webmaster/ru/new-doctors4agents.xml).

### Описание дополнительных элементов фида

К [элементам фида](https://yandex.ru/support/webmaster/ru/search-appearance/doctors#description-elements) добавляется дополнительный элемент `agent_info` содержимого `shop`.

Обязательные элементы отмечены символом `*`.

**Элементы содержимого `shop`**

| Элемент | Количество | Тип | Описание |
| --- | --- | --- | --- |
| `name` * | 1 | String | Название площадки для отображения в карточке врачей. Допустимый размер — 30 символов. Отображается в списке сайтов для записи на прием и в карточке врача в разделе **Контакты и ссылки**. |
| `company` * | 1 | String | Название организации. Используется при проверках, в карточке врача не отображается. |
| `url` * | 1 | String | URL-адрес площадки или сайта клиники. |
| `picture` * | 1 | String | Ссылка на логотип площадки или клиники. Требования к изображению: минимальный размер — 100 × 100 пикселей. Логотип может быть на фоне любого цвета. Дополнительно вписывать логотип в круг не нужно. Логотипы на белом фоне должны занимать максимальную площадь изображения. Это поможет повысить узнаваемость бренда площадки. |
| `email` | 0-1 | String | Адрес электронной почты для обращений. |
| `doctors` * | 1 | Набор элементов | Перечень описаний врачей. Должен содержать не менее одного элемента `doctor`. |
| `clinics` * | 1 | Набор элементов | Перечень описаний клиник. Должен содержать не менее одного элемента `clinic`. |
| `services` * | 1 | Набор элементов | Перечень описаний услуг. Должен содержать не менее одного элемента `service`. |
| `offers` * | 1 | Набор элементов | Перечень описаний услуг, которые врач оказывает в клинике. Должен содержать не менее одного элемента `offer`. |
| `agent_info` | 0-1 | Набор элементов | Информация об агенте, предоставляющем данные для клиники. |

**Элементы содержимого `agent_info`**

| Элемент | Количество | Тип | Описание |
| --- | --- | --- | --- |
| `name` * | 1 | String | Название агента для отображения. |
| `company` * | 1 | String | Официальное название организации-агента. |
| `url` * | 1 | String | URL-адрес сайта агента. |
| `picture` | 0-1 | String | Ссылка на логотип агента. Требования к изображению: минимальный размер — 100 × 100 пикселей. Логотип может быть на фоне любого цвета. Дополнительно вписывать логотип в круг не нужно. |
| `email` | 0-1 | String | Адрес электронной почты агента. |
| `contract` * | 1 | String | № договора агента с клиникой на предоставление данных о врачах и услугах клиники в Яндекс. |
| `inn` * | 1 | String | ИНН организации агента. |

> 0-1 — не более одного.

## Работа с несколькими технологическими партнерами

Если клиника взаимодействует с несколькими технологическими партнерами, размещение осуществляется на основе данных партнера, который первым подключил клинику к партнерской интеграции. Чтобы сменить партнера, необходимо отключить размещение через ранее подключенных партнеров, после чего можно выполнить повторное подключение через нужного партнера.
